# Formalization Rules

## Prefer high-value blocks

- Problem formulation that defines variables, inputs, outputs, objectives, and constraints.
- Algorithm blocks that compress real implementation or method steps.
- Equations that define metrics, losses, rewards, probabilities, constraints, or transformations.
- Definitions that remove ambiguity in repeated terms.
- Propositions or lemmas when a property follows from stated assumptions.
- Theorems only when the claim is central and proof conditions are explicit.

## Quantity policy

Actively search for all valid opportunities, but accept only blocks that improve rigor, reproducibility, or clarity. More blocks are useful only when each block earns its place.

## Required metadata per block

- type
- manuscript placement
- source or evidence
- purpose
- symbol list
- claim boundary
- LaTeX dependency
- verification need

## Rejection reasons

- decorative formula
- unsupported theorem
- undefined symbols
- not referenced in text
- duplicates existing content
- conflicts with code or evidence
- too broad for the approved claim gate
